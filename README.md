# إعداد اختبار Ausbildungsaufnahme

منصة شاملة للتحضير لاختبارات اللغة الألمانية المطلوبة لبرامج Ausbildung في ألمانيا

## المميزات

- اختبارات محاكية تمامًا لـ Goethe-Zertifikat B1/B2 و telc Deutsch B1/B2 Beruf و ÖSD Zertifikat B1/B2
- واجهة عربية بالكامل مع دعم كامل للاتجاه من اليمين إلى اليسار (RTL)
- تصميم لعبيد وممتع بألوان علم ألمانيا (أسود وأحمر وأصفر)
- نظام تسجيل الدخول والاشتراكات
- لوحة تحكم شخصية لمتابعة التقدم والإحصاءات
- شرح تفصيلي لكل سؤال بعد إتمام الاختبار
- إمكانية إعادة الاختبارات عدد غير محدود من المرات
- شهادات إتمام بعد كل اختبار ناجح

## المتطلبات التقنية

- Node.js версии 16.0.0 أو أحدث
- npm (يأتي مع Node.js)
- Supabase (للقاعدة البيانات والمصادقة)

## التثبيت والتشغيل المحلي

1. استنساخ المستودع:
   ```bash
   git clone <repository-url>
   cd ausbildung-test-prep
   ```

2. تثبيت الاعتمادات:
   ```bash
   npm install
   ```

3. إعداد متغيرات البيئة (اختياري للتشغيل المحلي):
   المشروع يعمل محليًا بدون أي إعداد إضافي بفضل قيمة افتراضية آمنة لـ `JWT_SECRET`. لتخصيصها (موصى به دائمًا قبل أي نشر حقيقي)، انسخ `.env.example` إلى `.env` وعدّل القيم:
   ```bash
   cp .env.example .env
   ```
   انظر قسم "النشر على الإنترنت" أدناه لتفاصيل كل متغير.

4. تشغيل قاعدة البيانات:
   - قم بإنشاء مشروع جديد في Supabase
   - شغّل ملف الترحيل الموجود في `supabase/migrations/20240101000000_initial_schema.sql`
   - هذا سيقوم بإنشاء جميع الجداول اللازمة

5. تشغيل الخادم:
   ```bash
   npm run dev
   ```
   أو للإنتاج:
   ```bash
   npm start
   ```

6. افتح المتصفح وانتقل إلى:
   ```
   http://localhost:3000
   ```

## النشر على الإنترنت

### ⚠️ لن يعمل المشروع على GitHub Pages

هذا مهم: **GitHub Pages يخدم ملفات ثابتة فقط** (HTML/CSS/JS/صور). هذا المشروع تطبيق **Node.js/Express حقيقي** — `server.js` يشغّل عملية خادم فعلية تتعامل مع تسجيل الدخول ولوحة التحكم والاختبارات وكل ما هو تحت `/api/*`. GitHub Pages لا يمكنه تشغيل `node server.js` أو إبقاء أي عملية خادم قائمة على الإطلاق. رفع المشروع إلى GitHub (كمستودع كود) أمر جيد ومطلوب، لكن **تفعيل GitHub Pages على هذا المستودع لن يعطي موقعًا يعمل** — فقط واجهة ثابتة بدون أي وظائف حقيقية (لا تسجيل دخول، لا اختبارات، لا لوحة تحكم).

### الاستضافة الصحيحة: منصات تدعم Node.js وتتصل مباشرة بـ GitHub

أرفق المشروع بملف `render.yaml` جاهز لمنصة [Render](https://render.com) (تجربة مجانية متاحة، تدعم عمليات Node دائمة، وتُعيد النشر تلقائيًا عند كل `git push`):

1. ارفع المشروع إلى مستودع GitHub عادي (بدون تفعيل Pages).
2. في Render: **New → Blueprint** → اختر المستودع → سيقرأ Render ملف `render.yaml` تلقائيًا ويُعدّ كل شيء.
3. بعد أول عملية نشر، اذهب إلى تبويب **Environment** في Render وأضف قيمة حقيقية لـ `JWT_SECRET` (يمكن توليد قيمة عشوائية آمنة بالأمر التالي محليًا):
   ```bash
   node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
   ```
4. إن كنت تخطط لتوليد صوت حقيقي عبر `npm run audio` مباشرة على الخادم، أضف أيضًا `OPENAI_API_KEY` في نفس التبويب (أو ببساطة ولّد ملفات الصوت محليًا وارفعها ضمن المشروع، انظر القسم أدناه).

بدائل أخرى تدعم Node.js بنفس الطريقة (اتصال مباشر بـ GitHub، إعادة نشر تلقائية): [Railway](https://railway.app)، [Fly.io](https://fly.io)، أو أي خادم افتراضي (VPS) عادي يدعم تشغيل `npm install && npm start`.

### ملف صوت الاستماع عند النشر

مجلد `public/audio/*.mp3` مُستثنى من git عمدًا (ملفات كبيرة يمكن توليدها من جديد، وليست كودًا مصدريًا). عند النشر على أي منصة، لديك خياران:
- شغّل `npm run audio` مباشرة على الخادم بعد الرفع (يتطلب ضبط `OPENAI_API_KEY` هناك)، أو
- ولّد الملفات محليًا كما تفعل الآن، ثم احذف السطر `public/audio/*.mp3` من `.gitignore` وارفعها ضمن المستودع مباشرة (الأبسط إن لم تكن تخطط لتوليد صوت جديد كثيرًا).

## واجهات برمجة التطبيقات (API)

### المصادقة
- `POST /api/auth/register` - تسجيل مستخدم جديد
- `POST /api/auth/login` - تسجيل الدخول
- `POST /api/auth/logout` - تسجيل الخروج
- `GET /api/auth/status` - التحقق من حالة المصادقة

### الاشتراكات
- `GET /api/subscription/status` - الحصول على حالة الاشتراك
- `POST /api/subscription/` - إنشاء/تجديد الاشتراك
- `DELETE /api/subscription/` - إلغاء الاشتراك

### الاختبارات
- `GET /api/tests/` - الحصول على قائمة الاختبارات المتاحة
- `GET /api/tests/:testId` - الحصول على تفاصيل اختبار معين (أقسام + نموذج كتابة)
- `POST /api/tests/attempts` - بدء محاولة اختبار جديدة
- `PUT /api/tests/attempts/:attemptId` - إرسال محاولة اختبار
- `GET /api/tests/attempts` - الحصول على محاولات المستخدم
- `GET /api/tests/attempts/:attemptId` - الحصول على تفاصيل محاولة معينة

**محتوى الاختبارات:** تم بناء كل اختبار (`api/tests.js`) ليعكس البنية الحقيقية للاختبار الرسمي المقابل — نفس أسماء الأقسام، عدد أقسامها، ونوع الأسئلة، بالاستناد إلى الأدلة الرسمية لمعهد جوته و telc و ÖSD:
- **Lesen / Leseverstehen** (القراءة) و **Sprachbausteine** (التراكيب اللغوية): أقسام مُقيَّمة آليًا بنفس أنواع الأسئلة الرسمية (Richtig/Falsch، اختيار من متعدد، Zuordnung/المطابقة)، وبنفس عدد الأجزاء الرسمي (مثلاً 5 أجزاء لـ Goethe B1 Lesen، أو Teil 1/2/3 لـ telc Leseverstehen).
- **Hören / Hörverstehen** (الاستماع): تدريب عبر نص مكتوب (Transkript) بدل ملف صوتي حقيقي — المنصة لا تدعم بعد رفع/تشغيل ملفات صوتية.
- **Schreiben / Schriftlicher Ausdruck** (الكتابة): تدريب حر غير مُقيَّم آليًا، مع نموذج إجابة يمكن للطالب مقارنة إجابته به.
- **Sprechen / Mündlicher Ausdruck** (المحادثة): غير متوفر — يتطلب اختبارًا شفهيًا حيًّا لا يمكن لتطبيق ويب محاكاته.

عدد الأسئلة الفعلي في كل تدريب (60–74 سؤالًا حسب الاختبار) يقترب الآن من العدد الرسمي الفعلي لأقسام Lesen/Leseverstehen وSprachbausteine وHören المُقيَّمة آليًا (مثال: telc B1 Beruf يطابق العدد الرسمي بدقة: 20+20+20=60). في بعض الاختبارات (خصوصًا Goethe) تمت إضافة قسم Sprachbausteine كتدريب إضافي غير رسمي لتعزيز التحضير. حيث لم يُنشر عدد دقيق رسميًا (توزيع Lesen/Sprachbausteine لدى ÖSD تحديدًا)، استُخدم تقدير معقول مبني على نفس نمط الأسئلة الرسمي بدل رقم مختلق. الحقل `total_questions` في بطاقات الاختبارات بالصفحة الرئيسية يعكس العدد الرسمي المُقيَّم فقط (Lesen+Hören)، بينما `trial_question_count` في لوحة الطالب يعكس العدد الفعلي المتاح للتدريب (يشمل أقسام إضافية عند وجودها).

### لوحة تحكم المشرف (Admin)
جميع المسارات التالية تتطلب توكن مشرف (role = admin):
- `GET /api/admin/stats` - إحصائيات عامة (إجمالي الأعضاء، قيد المراجعة، نشط، مرفوض، اشتراكات فعالة)
- `GET /api/admin/members?status=&q=` - قائمة الأعضاء مع تصفية حسب الحالة والبحث
- `POST /api/admin/members/:id/approve` - الموافقة على عضو (يُفعّل اشتراكه لـ3 أشهر)
- `POST /api/admin/members/:id/reject` - رفض عضو
- `POST /api/admin/members/:id/reset` - إعادة عضو إلى حالة "قيد المراجعة"
- `DELETE /api/admin/members/:id` - حذف عضو نهائيًا
- `GET /api/admin/notifications` - سجل الإشعارات المرسلة
- `POST /api/admin/notifications` - إرسال إشعار لجمهور محدد (الكل / نشط / قيد المراجعة / مرفوض)

الوصول إلى لوحة التحكم: `http://localhost:3000/admin.html`

**حساب مشرف تجريبي (مُهيّأ تلقائيًا عند تشغيل الخادم):**
```
admin@ausbildung-test-prep.com / Admin@2024
```
عند تسجيل حساب جديد من الموقع، تكون حالته `pending` (قيد المراجعة) حتى يوافق عليه مشرف من لوحة التحكم — وهي النقطة المخصصة للتحقق اليدوي من الدفع قبل منح الوصول الكامل.

## توليد صوت حقيقي لأقسام الاستماع (Hören)

أقسام الاستماع تعرض حاليًا نصًا مكتوبًا (Transkript) بدلًا من ملف صوتي حقيقي. لتوليد صوت ألماني حقيقي لكل قسم استماع، شغّل السكريبت التالي (مرة واحدة، خارج التطبيق):

```bash
export OPENAI_API_KEY="sk-..."   # من https://platform.openai.com/api-keys
node scripts/generate-audio.js
```

- يقرأ السكريبت كل قسم استماع من `api/testsContent.js`، وينظّف النص (يحذف علامات المتحدثين مثل "A:" أو "Moderator:" وترقيم القوائم) قبل تحويله لصوت طبيعي.
- يحفظ الملفات في `public/audio/` بأسماء متوقعة (`<testId>__<sectionKey>.mp3`)، والتطبيق (`api/tests.js`, `public/dashboard.html`) يبحث عنها تلقائيًا — بمجرد وجود الملف، سيظهر مشغّل صوت حقيقي في لوحة الطالب بدل النص فقط، بدون أي تعديل إضافي في الكود.
- **التكلفة تقريبية ولمرة واحدة فقط**: كل محتوى الاستماع الحالي حوالي 10 آلاف حرف، أي أقل من دولار واحد إجمالاً (وليست تكلفة لكل طالب، لأن الملفات تُولَّد مرة واحدة وتُخدَّم كملفات ثابتة للجميع).
- السكريبت قابل لإعادة التشغيل بأمان: يتجاوز أي ملف موجود مسبقًا (استخدم `--force` لإعادة توليد كل شيء).
- إن لم يُشغَّل السكريبت أبدًا، يعرض التطبيق النص المكتوب تلقائيًا (كما كان سابقًا) — لا يوجد كسر في الوظائف.
- لتبديل مزوّد الصوت (مثلاً Google Cloud TTS الأرخص، أو ElevenLabs الأعلى جودة)، يكفي تعديل دالة `synthesizeSpeech()` في أعلى السكريبت — باقي المنطق (اكتشاف المحتوى، تسمية الملفات، إمكانية الاستئناف) يبقى كما هو.

## ملاحظات هامة

1. هذا المشروع يستخدم واجهات برمجة تطبيقات وهمية (Mock API) لأغراض التوضيح.
2. في الإصدار الإنتاجي، يجب استبدال هذه الواجهات بتكامل حقيقي مع Supabase.
3. يجب استبدال قيم `JWT_SECRET` ومفاتيح Supabase بقيم آمنة في بيئة الإنتاج.
4. لمعالجة الدفع الحقيقي، يجب دمج خدمة مثل Stripe أو بوابات دفع محلية.
5. محتوى الاختبارات تدريبي وليس مطابقًا حرفيًا للاختبار الرسمي؛ لا تُعتبر المنصة بديلاً عن التسجيل في مركز امتحان معتمد.
6. الصوت المُولَّد بواسطة `scripts/generate-audio.js` يتطلب مفتاح OpenAI API خاصًا بك (غير مُضمَّن)؛ راجع قسم "توليد صوت حقيقي" أعلاه.
